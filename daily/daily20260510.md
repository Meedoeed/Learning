# PS

Как дипломную работу выбрал тему относительного программной реализации планировщика развертывания с учётом ретроспективного анализа трейсов приложений. План по выполнению прилагаю ниже.

Проект представляет собой веб-приложение для автоматического построения и визуализации графа ресурсов и зависимостей в распределенных микросервисных системах. Система собирает телеметрию из Kubernetes API, Prometheus и OpenTelemetry, нормализует данные в единую модель вершин и рёбер, сохраняет в графовую базу данных и предоставляет REST API для запросов подграфов по фильтрам. На основе собранного графа и ретроспективного анализа исторических метрик модуль-планировщик генерирует рекомендации по размещению сервисов на узлах кластера с учётом аффинити, доступных ресурсов и статистики отказов.

Для чего:

Проект решает проблему фрагментированного представления о зависимостях в микросервисной архитектуре. Инженеры и SRE-команды получают единый инструмент, который отвечает на вопросы: какие сервисы пострадают при отказе базы данных, какие цепочки вызовов самые дорогие по latency, как оптимально разместить новые экземпляры сервисов чтобы избежать каскадных сбоев. Режим анализа инцидентов подсвечивает пути деградации в реальном времени на основе метрик p95 latency и error rate. Экспорт графа в GraphML, DOT и PNG позволяет использовать результаты в сторонних анализаторах и документации.
